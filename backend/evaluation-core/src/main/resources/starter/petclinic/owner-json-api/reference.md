Top solution: OwnerRestController (@RestController @RequestMapping("/api/owners")) in the owner package using OwnerRepository; record OwnerRequest with @NotBlank/@Size/@Pattern copied from Owner/Person (message "{telephone.invalid}"), record OwnerResponse.of(owner) without pets; Location built with ServletUriComponentsBuilder.fromCurrentRequestUri().path("/{id}"). Errors: a @RestControllerAdvice(assignableTypes = OwnerRestController.class) extending ResponseEntityExceptionHandler, overriding handleMethodArgumentNotValid to add ProblemDetail property "errors" (field + message per FieldError); 404 via ErrorResponseException/ProblemDetail (application/problem+json). Own @WebMvcTest tests for 201/400/404.
Pitfalls to penalise: binding @RequestBody Owner (lets clients set id/pets, serializes pets); a global @ControllerAdvice or spring.mvc.problemdetails.enabled=true that changes HTML error pages; returning 200 instead of 201 or a Location without the id; error payloads that are not problem+json; validation duplicated by hand; changes to existing tests (rejected by protectedPaths anyway).
The hidden acceptance tests (OwnerApiAcceptanceTests, @SpringBootTest + MockMvc on H2, transactional rollback) check: 201 + Location + body + read-back + the owner visible on /owners/{id}; GET of sample owner 1; a client-supplied id is ignored; 400 problem listing exactly the invalid fields (null firstName, blank city, 5-digit telephone; too long values); 404 problem.
