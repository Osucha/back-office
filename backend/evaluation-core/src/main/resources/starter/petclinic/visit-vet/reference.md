Top solution: nullable vet_id + FK (+ index) in the three schema files, H2 DROP order with visits first; positional inserts in h2/mysql data.sql extended with a fifth value (2, NULL, 3, NULL), postgres inserts get vet_id in the column list. Visit: @ManyToOne @JoinColumn(name = "vet_id") Vet vet (EAGER default, needed because open-in-view is off). Binding: a public @Component VetFormatter implements Formatter<Vet> (print = id, parse = VetRepository.findById or ParseException -> typeMismatch field error); empty strings never reach the formatter (bound as null). VetRepository gains Optional<Vet> findById(Integer) (uncached). VisitController gets VetRepository and @ModelAttribute("vets") = findAll(). Template: th:field="*{vet}" select with an empty option (#{none}) and th:each options value=${v.id} text=${v.firstName + ' ' + v.lastName}; ownerDetails gets a Vet column (#{vet}). VisitControllerTests: @MockitoBean VetRepository, includeFilters for VetFormatter (Formatter beans are not part of a @WebMvcTest slice), tests for vet / empty / unknown id.
Pitfalls to penalise: forgetting the positional inserts (H2 startup fails, MySQL data load fails), FetchType.LAZY without a fetch join (LazyInitializationException on the owner page), parsing the id by hand in the controller and silently ignoring unknown ids, only English text in translated files, editing other existing tests.
Hidden tests (VisitVetAcceptanceTests, @SpringBootTest + MockMvc, each request its own transaction, own owner/pet per test): select named vet with an empty option and all six vets; a visit with vet=5 shows "Henry Stevens" in its row on the owner page; empty and missing vet work; unknown id -> 200 form with a field error on visit.vet and nothing saved; sample data rows of owner 6 (Helen Leary on 2013-01-01, Linda Douglas on 2013-01-03, none on the others); MySQL/PostgreSQL schema text has a nullable vet_id referencing vets; positional visits inserts have five values.
