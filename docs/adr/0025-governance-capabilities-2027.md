# 0025 - Governance capabilities for 2027: budgets, delivery insights, AI provenance, MCP

Status: accepted - 2026-09-28

## Context
By 2027 engineering leaders running agentic delivery need four things beyond "agents that work":
spend they can cap, evidence of what the agents did (for audits, the EU AI Act transparency duties and
customers), metrics that show where delivery actually waits, and access to the platform from wherever
engineers and other agents already work (IDEs, chat, other agents). Back Office sees every run, gate,
token and diff, so it is the natural place to provide them.

## Decision
1. **Budgets with hard stops.** Monthly limits per project and platform-wide, per-run and per-job caps on
   the task template; alerts at a threshold; when a hard limit is reached the LLM gateway refuses new
   calls with `budget-exceeded`, running jobs end gracefully, and a `you` turn card asks an owner to raise
   the limit or stop.
2. **Delivery insights.** Computed from the run, gate, CI and usage tables: lead time issue → merge
   request, human wait time at gates (the bottleneck the platform exists to shrink), agent success rate per
   template and model, rework loops, cost per successful run and per merged change, throughput per week,
   model mix. Read-only, filtered by the caller's projects.
3. **AI provenance attestations.** Each runner job and each completed run gets an **in-toto Statement v1**
   (`predicateType: https://back-office.dev/attestations/agent-run/v1`) wrapped in a **DSSE** envelope
   signed with the platform's Ed25519 key (public keys published at `/.well-known/back-office/keys`).
   Subjects are the commit SHA and diff digest; the predicate records workflow and template versions,
   model and effort, prompt digests, sandbox policy, egress log digest, tokens and cost, verification
   result and approving humans. Downloadable from the run page and verifiable offline.
4. **MCP server.** Back Office exposes a Model Context Protocol server (streamable HTTP at `/mcp`,
   authenticated with personal access tokens and the caller's permissions) with tools to list work waiting
   for the caller, read runs and artefacts, start workflows, search the task library and fetch project
   context. Engineers' IDE agents and other agents can then use the platform as a tool.

## Alternatives
- External FinOps and analytics tools: useful later, but they lack the gate and template context.
- SLSA build provenance only: covers builds, not agent decisions or human approvals.

## Consequences
- The signing key is a new secret (generated by the chart, rotatable, old keys stay published).
- MCP tools go through the same use cases and `AuthorizationGate` as REST.
